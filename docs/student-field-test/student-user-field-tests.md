# 普通大学生使用 Arkive 的实地测试

这是一份待执行的真实用户任务清单。测试者模拟一位平时保存课件、作业、小组展示、社团照片与录像，学期末需要整理资料的大学生。通过正常界面和真实 Agent 对话完成任务，观察文件结果及使用感受，不用固定模型回复代替真实模型。

本计划根据当前项目界面、Agent 工具与 `skills/` 文档编写，尚未执行。三个业务 Skill 当前未自动加载；本轮可以先验证现有 Agent 与业务链路，后续接入 Skill 后再用相同素材副本对比。

## 先准备这些文件

大小为便于测试的建议，不是格式支持条件，也不保证一定有压缩收益。不必凑足数量，先提供每类有代表性的文件即可。

| 材料                 | 建议数量与大小                           | 需要包含什么                                                                | 用途                                       |
| -------------------- | ---------------------------------------- | --------------------------------------------------------------------------- | ------------------------------------------ |
| JPG／JPEG 照片       | 3–5 张，每张约 2–15 MB                   | 手机实拍、合照或活动照片；至少一张有细节和暗部                              | 图片质量、批量选择、标签归档               |
| PNG 图片             | 2 张                                     | 一张带透明背景的社团 Logo／图标，一张包含小字的截图                         | 透明度、小字清晰度、格式选择               |
| PDF                  | 2–3 份，约 5–80 MB                       | 一份文字／公式课件，一份扫描或大量图片的课程资料；可另加已优化的小 PDF      | 无损与有损档位、页面与文字检查、无收益情况 |
| DOCX                 | 1 份，约 5–40 MB                         | 插入数张大照片的实验报告，带表格、标题或公式；使用普通未加密文档            | 嵌入图片压缩、原路径替换、原件备份         |
| PPTX                 | 1 份，约 20–100 MB                       | 有多张大图的小组展示；嵌入短 MP4 可选，不必为了测试专门制作                 | 原位压缩、版式与播放检查                   |
| MP4 视频             | 2 段，每段约 30–90 秒、50–300 MB         | 普通 SDR／非 HDR，带 AAC 音轨；一段可用手机或相机录制，另一段可稍长用于取消 | 视频探测、HEVC 压缩、音画检查、取消        |
| 大疆 Pocket 原片     | 可选 1 段                                | 直接复制相机原文件，不预先转码；保留拍摄模式信息                            | 设备附加内容提示与真实设备兼容性           |
| 当前不支持压缩的资料 | XLSX、CSV、ZIP、IPYNB、TXT 中任选 2–3 份 | 普通表格、课程代码或打包作业即可                                            | 混合文件夹中能否保留未支持项、如实解释     |
| 边界材料             | 可选                                     | 一份带密码的 PDF，或一段明确知道是 HDR 的录像                               | 对不支持特性说明原因并保留原件             |

MP4 是容器名，不能单凭扩展名保证可处理；不清楚视频编码时可以先提供原片，由工具探测。视频会重新编码为 HEVC MP4，不能将其描述为无损视频转换。

使用真实课程／活动材料的副本即可，内容可脱敏。无需提供真实邮箱账号、聊天数据库、API 密钥或私密聊天记录。微信和邮件场景可以用上述资料的导出副本模拟，保留有意义的文件名；若没有真实导出来源，报告中标为“模拟附件集合”，不能写成已验证真实微信／Mail 集成。

测试布置时再制作重复副本、不同内容的同名文件、中文空格文件名和已经存在的目标文件。素材提供者无需逐项手工准备这些变体。

使用自然语言先完整走一次，允许正常追问与澄清；不要一开始就告诉 Agent 工具名或预期答案。若失败，再用另一份副本从界面或给出明确操作要求复查，区分交互理解、模型服务和文件业务问题。

## 八个主要用户任务

### 1. 刚装好软件：不知道从哪里整理

**素材**：一个含 PDF、DOCX、照片、短录像和 XLSX／ZIP 的混合课程资料目录。

**用户原话**：

> 这学期文件越存越多，这个文件夹有点乱。你先看看哪里比较占空间，有什么整理建议，先别改文件。

先提供该测试目录的完整路径，观察 Agent 会如何理解需求。如果追问，按真实偏好回答，例如“课件和作业都要留，录像很少看”。这项到建议交付结束，不同意任何修改。

**观察重点**：只检查指定范围；建议能对应实际文件，而不是一套泛泛的清理话术；清楚解释压缩、原件备份和归档各自用途；未支持文件有说明。母本和本项输入没有被移动、覆盖、打标签或清理。只读工具自身的临时文件不算修改用户输入。

### 2. 交作业前：课程 PDF 太大

**素材**：文字／公式 PDF 与扫描 PDF 各一份。

**操作**：先从文档／压缩界面选择扫描 PDF，按界面提供的档位处理，查看进度和结果；再用另一份副本询问 Agent：

> 这份课程资料有点大，我要发给同学。先看看能不能缩小，里面的小字和公式要看得清。

Agent 给出处理方式和原件变化后，授权其中一种方案。可以再补充“这一份先不用归档”，留下待归档结果用于任务 8。

**观察重点**：文件选择／拖放、档位含义、进度、失败信息是否易懂；Agent 能否区分无损优化与会影响图片的档位；输出能打开，页数、公式、表格、扫描小字和页面方向是否正常。记录实际大小，无收益可以是正确结果，不要求每个 PDF 都变小。

### 3. 小组展示：PPT 图片多、文件太重

**素材**：含大图的普通 PPTX；有嵌入视频更好，但不是必需。

**操作**：从界面选择文件，阅读替换原文档的提示，先不勾选／确认替换观察界面，再确认并压缩。成功后选择归档，给出“小组项目”或用户实际项目标签。

**用户问题**：

> 这个展示文件太大了。压缩之后我的原版还在吗？以后发现图片不好看，能找回原版吗？

**观察重点**：用户在执行前能否知道原路径将是新文档、完整旧版在 Backup；没确认时不会直接替换。用 PowerPoint／兼容查看器打开结果，对照母本检查标题、文字、图片、图表、备注和动画；有视频时实际播放并听声音。检查备份旧版也能打开，Archive 中的是哪一份应明确。

### 4. 社团招新：活动照片和透明 Logo

**素材**：3–5 张 JPG、一张透明 PNG Logo、一张小字截图；混入一个不支持压缩的文件。

**操作**：把这一批文件拖入压缩界面，观察分类和未支持项提示。针对 Logo 保留透明格式，查看图片输出选项；照片选择常用档位，完成后把实际成功的结果归档。再问 Agent：

> 刚才那批招新照片，帮我看看归档里有没有，按“社团”和“招新”加标签，之后我想按活动找。

Agent 展示拟处理记录和标签后确认应用。没有归档成功的项不应被当成可打标签记录。

**观察重点**：支持文件继续处理，其他文件保留；透明背景未意外变黑／变白，小字可读，人脸、暗部和边缘没有不可接受的变化。标签实际落到正确资料，原输出与 Backup 不应被误当成同一份归档。Mac 上核对 Finder 标签。

### 5. 演唱会或校园活动：珍贵录像太大

**素材**：一段带声音的 SDR MP4；可额外用一段大疆原片。

**用户原话**：

> 这是我拍的校园演出视频，想留着以后看，但有点占空间。帮我看看怎么处理，画面和声音尽量保留好。

观察探测结果和建议。确认完整输入、输出位置、格式、附加内容损失及 Backup 行为后，授权压缩并归档；使用实际活动名称或日期作标签。

**观察重点**：Agent 先探测而非凭后缀判断；没有虚构演出人物、拍摄地点或效果数字。大疆文件有辅助内容时能说明将移除什么。播放输出的开头、中间、结尾，检查声音、同步、时长、画幅、颜色、细节与查找拖动；同时保留“程序检查通过”和“用户实际播放可接受”两类结论。

**继续追问**：

> 现在原视频在哪里？它变小了，是不是我的电脑已经空出了这么多空间？

回答应指出实际原件路径，并解释 Backup、输出和 Archive 都可能占空间，不能把压缩体积差直接说成磁盘已经释放的容量。

### 6. 学期末：微信收到的资料找不到、还重复

**素材**：模拟或真实导出的可读附件目录，含 PDF、DOCX、图片、一个未支持文件；两份内容相同但名称不同的文件，以及两个不同子目录里同名但内容不同的文件。

**用户原话**：

> 这些是我从班级群里存下来的文件，有重复的，也有作业和课件。帮我整理，重要的留下来，以后按名字能找到。先给我方案。

用户澄清“作业和课件要留”。先查看方案，再授权明确的一批压缩归档操作；第一轮不授权清理。随后可单独选一份已经展示、确认不再需要的独立重复副本移入回收站。

**观察重点**：同名不同内容不会被合并；重复判断有内容依据；未支持文件没有被遗漏或谎称已归档。处理范围限于导出目录，不能扩大到整个微信。明确这次处理的是附件集合，不能声称聊天记录、发送者或加密数据库已经备份。后续只移除用户选定的副本。

### 7. 毕业整理：保留课程／项目邮件附件

**素材**：按课程或项目分好的附件目录，含 PDF、带图片的 DOCX、PPTX、XLSX／ZIP。可用已有材料复制布置，不要求连接真实邮箱。

**用户原话**：

> 我毕业了，想把大学期间值得保留的邮件附件整理好。这个目录是我导出来的资料，报告和课件要留，先别删邮件。

观察能否从已给目录进入实际检查，而非要求重复说明年份。授权一批可支持文件压缩归档，保留未支持项。

**继续追问**：

> 这些归档好了，我是不是可以把原来的邮件都删了？

**观察重点**：DOCX 打开后检查图片、表格、公式、页眉页脚和版式；Agent 能解释附件归档没有包含正文、主题与往来记录，不能因附件已归档就代替用户决定删除邮件；不能把文件修改时间当收发日期，也不能声称已连接或清理邮箱。

### 8. 隔天回来：没有聊天记录也能找资料

**前置**：至少有几份已归档记录，以及任务 2 中仅压缩、未归档的一份 PDF。

**操作**：完整退出再启动应用。先从“我的归档”搜索文件名、按标签筛选、打开或定位；查看原件备份区和待归档结果区。再新建真实对话：

> 在归档库里找一下之前的社团招新照片，找到后帮我在 Finder 里显示。

接着：

> 我之前压缩了一份课程 PDF，还没归档。帮我找出待归档的结果，给我看一下是哪份。

确认正确记录后授权归档。再移除一个旧标签并加一个新标签，核对界面和 Finder 的实际变化。

**观察重点**：不依赖上一轮聊天上下文，能从持久 Catalog 找到记录；待归档任务不重新编码原文件。检查归档记录、路径、标签和旧版 Backup 对应正确，不只看聊天里写了“完成”。当前聊天会话仅在内存，重启后不保留是已知边界，归档库重启后仍应可用。

## 四个补充任务

### 9. 保留多个路径的 APFS 去重

Mac 同一 APFS 卷中，对一份测试文件做两份完全相同的副本。先在工具箱扫描，再询问 Agent“这些副本都得留在原文件夹，有没有不降低内容质量的办法？”

确认明确源、副本路径及克隆替换的含义后执行。核对所有路径仍在、文件可打开；在独立副本上由测试者修改其中一份，检查其他文件内容不受连带修改。已有 APFS 克隆可能被跳过，不能强制要求每份 Finder 复制得到的文件都有新增共享量。逻辑共享量不作为实测释放空间。

### 10. 临时改主意：停止生成或取消压缩

用另一份较长录像，在探测、选参或编码尚未提交时点击取消，观察界面、Agent 状态和输入文件。需要再次测试时重新取副本。

停止聊天生成与已经提交的文件操作要分开判断；未提交的处理应停止并保留输入，进入提交阶段的动作可能完成，界面和回复应报告实际结果。随后新建对话或处理另一份小文件，确认应用仍能使用，而非永久卡在“处理中”。

### 11. 现实小麻烦：无收益、不支持、同名目标

分别测试已经优化的小文件、带密码 PDF／HDR 视频，以及目标路径已存在的情况。再混用中文、空格和较长文件名。

无收益是可接受业务结果；文件不能为了显示成功而被不必要地再次压缩。不支持项应保留并说明原因。同名目标未获覆盖授权时不能被覆盖，界面／Agent 应给出可执行的下一步。三种情况分开记录，避免把其中一种失败原因套到其他文件。

### 12. 开发课程项目与工具箱预览

可选准备一个可丢弃的课程代码副本，例如含 `README.md`、`.ipynb`、源码与本地可重建目录的项目。先问“这个旧课程项目哪里占空间？先检查，别删”，观察分析是否结合具体证据，而不是按目录名直接删除。

如需测试系统清理预览，在独立测试账户上明确要求预览，再观察清理章节、候选与提示。这不是限定到素材目录的扫描；`mole_clean_preview` 本身没有目录参数，不把它描述成只扫描该项目。第一轮到预览结束，不进行系统提权、卸载或实际清理。若另测 Purge，当前工具扫描配置过的项目位置，也不能承诺会自动覆盖这个测试目录。

## 如何判断这轮有收获

每项分别填写功能结果与使用体验，不要求 Agent 按某句固定话术作答。

| 记录项       | 填写内容                                                                                       |
| ------------ | ---------------------------------------------------------------------------------------------- |
| 功能结果     | 通过／部分完成／失败／环境不具备／当前未实现；无收益另写原因，不自动判失败                     |
| 真实文件证据 | 输入、输出、Backup、Archive、记录 ID、前后字节数、打开结果；必要时和母本比较内容哈希           |
| 对话体验     | 能否听懂自然表达；关键影响是否提前说明；用户已确认后是否仍逐文件重复追问；失败后下一步是否清楚 |
| 界面体验     | 是否找得到入口和结果；进度与取消是否清楚；重启后能否找回；错误能否理解                         |
| 问题严重程度 | 文件丢失／覆盖／越权；结果错误；流程走不通；解释或易用性问题，分别记录                         |
| 证据         | 对话截图、结果页截图、实际打开文件截图及必要日志，隐藏个人信息和密钥                           |

第一轮优先完成任务 1–5 与 8，先确认“询问 → 理解 → 压缩 → 备份 → 归档 → 找回”完整主线；再做微信、邮件和补充任务。真实微信／Mail 数据目录专项集成、Skill 加载效果、模型更换后的差异应另列，不能仅凭模拟附件任务通过而宣称已经验证。

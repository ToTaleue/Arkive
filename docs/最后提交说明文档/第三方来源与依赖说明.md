# Arkive 第三方来源与依赖说明

更新日期：2026 年 10 月 18 日。适用项目：Arkive 1.0.0。

本文说明 Arkive 使用的第三方依赖包、随包本地工具、相关开源项目及模型 API 的用途、来源和授权依据。组件版本以当前 `package.json`、`pnpm-lock.yaml` 和 `resources/tools/darwin-arm64/manifest.json` 为准。

当前直接声明依赖 36 项，锁文件包含 930 个唯一包版本，均有许可元数据记录。本文已补充许可原文附件。Ghostscript 曾用于 PDF 压缩评估与对照，本轮已从随包工具和 PDF 调用路径删除；当前文档保留历史评估来源，qpdf-only 版本已重新构建并核对。当前不能把评估构建作为“已完成开源合规、可直接分发”的结论。直接依赖的声明范围、锁定版本已与现有附件复核一致；随包工具清单与当前 manifest 一致，其中记录的二进制 SHA-256 已与仓库内相应文件核对。哈希用于识别文件，不代表已经完成全部许可义务核验。

### 二进制取得渠道

- **FFmpeg／FFprobe**：来自 Martin Riedl 提供的 macOS ARM64 构建。manifest 保留下载地址、发布方校验地址与构建脚本仓库；`licenses/ffmpeg-license.txt` 和 `licenses/ffprobe-license.txt` 保留版本输出、配置参数与许可声明。当前构建启用了 GPL 组件，按随包程序的 GPL-3.0-or-later 声明记录，不套用 FFmpeg 默认 LGPL 许可。参见 [FFmpeg 官方许可说明](https://ffmpeg.org/legal.html)。
- **ab-av1**：来自 Homebrew core 的 macOS Sonoma ARM64 bottle，保留下载摘要、归档内路径与对应上游版本。
- **Mole、Czkawka CLI、qpdf**：分别来自对应上游的固定版本源码包或发布产物。Mole 包含上游脚本运行资源及 `analyze-go`、`status-go` 二进制；qpdf 同时包含 `libqpdf.30.4.2.dylib` 及 NOTICE。
- **pngquant**：来自 [pngquant 官网](https://pngquant.org/)的 macOS 二进制包，当前版本 3.0.3。已记录本地下载摘要和程序摘要；下载页没有单独的发布方校验值，确切源码与构建配置仍待补齐。官网同时提供 GPL 与商业许可选择，现有材料按 GPL 记录，未附商业许可证明。
- **SSIMULACRA2**：使用 rust-av 的 Rust CLI 移植，在固定提交 `05f2b4e216059d5c735f9665a51648a37d684e70` 本地构建；构建命令保留在 manifest。Cloudinary C++ 实现为评分标定参考，不作为当前随包程序来源。
- **Ghostscript（仅评估）**：从 Clop v3.5.0 固定提交 `21a71a0707c3c92907d569b2fa4ac7ac726ff713` 的工具归档中提取，曾用于 PDF 压缩效果评估与对照。manifest 区分了二进制提供方 [FuzzyIdeas/Clop](https://github.com/FuzzyIdeas/Clop/tree/21a71a0707c3c92907d569b2fa4ac7ac726ff713) 与 Ghostscript 上游；归档摘要与该提交的 Git LFS 指针对应。当前为预发布构建，确切 Ghostscript 源码提交、构建配置及内置资源声明未补齐，因此本轮已删除该二进制、调用路径和打包资源；qpdf-only 版本已重新构建并核对。授权渠道参见 [Artifex 官方许可说明](https://artifex.com/licensing)，现有材料按 AGPL 记录，未附商业许可证明。

### 项目自有原生工具

`arkive-apfs-dedupe` 由项目内 `native/apfs-dedupe.c` 经 `scripts/build-apfs-dedupe.mjs` 编译，用于 APFS 克隆替换、元数据核验和恢复。它是第一方工具，调用 macOS 系统能力，不列为第三方开源组件；来源清单保留其源码路径及二进制摘要，以便核对。

## 五、模型 API 服务

模型调用通过 Pi SDK 接入。当前项目配置使用以下外部服务：

| 项目 | 当前使用情况 |
| --- | --- |
| 服务提供方 | DeepSeek 官方 API |
| 接口根地址 | `https://api.deepseek.com` |
| 请求模型 ID | `deepseek-flash` |
| 模型名称 | 根据 2026 年 10 月 18 日查阅的官方接口文档，当前对应 DeepSeek-V4.1-Flash-1017；别名对应版本可能随服务方更新 |
| 项目用途 | Agent 对话、业务工具选择与结果总结，以及独立的文件标签推荐 |
| 接入方式 | 项目配置 `openai-compatible`；经 Pi SDK 调用兼容的 Chat Completions 接口。该配置名表示接口格式，不表示由 OpenAI 提供模型服务 |
| 授权依据 | 使用账号 API 凭据访问服务，受服务方开放平台协议约束；不随包提供或转授 API 密钥 |
| 上游资料 | [DeepSeek API 文档](https://api-docs.deepseek.com/)、[开放平台](https://platform.deepseek.com/)、[开放平台服务协议](https://cdn.deepseek.com/policies/en-US/deepseek-open-platform-terms-of-service.html) |

API 调用属于外部服务使用，不等同于模型权重再分发。项目不随包发布模型权重，不申报自研或微调基础模型，也未在本项目中训练模型。切换服务商或模型时，应同步更新本节来源与适用服务协议。

压缩和归档由本地工具执行；启用模型功能时，对话、工具结果以及调用方提供的文件名、路径、元数据和标签等信息可能发送至模型服务。当前自动标签主要基于名称、路径及整理后的元数据，不以此宣称完成图像、音频或文档正文识别。密钥由主进程读取，不写入本说明或清单附件。

# Arkive 项目说明书

Techathon 2026 参赛说明文档｜2026 年 10 月 18 日

## 一、项目简介

Arkive 是面向存量文件的桌面压缩与归档应用，优先支持 Apple 芯片 Mac。项目帮助用户处理不常用但仍有价值的视频、图片和文档：通过压缩减少文件体积，保存完整原件，并将需要长期保存的文件整理为可检索的归档。用户既可通过界面操作，也可通过产品 Agent 调用已有业务工具。

项目关注两个相连的问题：有价值的旧文件舍不得删、长期占用空间；文件整理后，难以再按活动、时间或用途找回。Arkive 将压缩、原件备份、归档、标签和检索连接起来，让用户在保留资料的同时管理存储。

## 三、功能说明与使用流程

### 当前功能

| 功能 | 功能说明 | 当前范围 |
| --- | --- | --- |
| 视频压缩 | 使用 FFmpeg 与 ab-av1，通过抽样 VMAF 选择编码参数，再压缩完整视频，检查输出及可解码性。 | 提供质量、均衡、体积档及 H.264 兼容模式；抽样评分不等于整片视觉无损保证 |
| 图片压缩 | 使用 Sharp／pngquant 按档位生成候选，检查尺寸、方向、透明度与元数据，并给出 SSIMULACRA2 评分及体积收益。 | 评分用于参考；不承诺所有图片都达到参考分或肉眼无损 |
| PDF 压缩 | 使用随包 qpdf 做无损结构优化，检查页数、结构及文档特征。当前交付不包含 Ghostscript。 | 支持四档结构优化；加密、数字签名及 PDF/A 不处理，部分档位限制表单、批注与附件 |
| Office 压缩 | 处理普通 DOCX／PPTX 内嵌图片和符合条件的视频，保留其他文档部件，整份校验与备份后在原路径发布。 | 实验性功能；复杂版式、字体、动画及媒体需在原生应用中检查 |
| 原件备份与归档 | Backup 保存完整原件，Archive 保存最终归档文件；支持压缩后归档、稍后归档和原样归档。 | 原样归档提供 Agent 入口；可按需保留原位置软链接，备份可经用户确认后移入回收站 |
| 标签与检索 | AI 根据原文件名、路径及已提取元数据推荐标签，写入 macOS 原生 Finder 标签，同时在 SQLite 中保存索引。支持名称、标签和日期筛选，以及打开、Finder 定位。 | 自动推荐可关闭，标签可手工增删；当前不提供全文、OCR 或语义向量检索 |
| 重复文件处理 | 使用 Czkawka 只读检测重复组，通过 APFS 克隆去重共享底层存储，保留文件路径和独立修改能力。 | 已有界面和 Agent 入口；源与副本须同一 APFS 卷，不将逻辑共享量当作实际释放空间 |
| 清理与工具箱 | 集成 Mole，提供磁盘分析、开发产物、安装包和应用候选审阅，以及独立 Clean 入口。 | 工具箱选定项目移入回收站；完整 Clean 沿用 Mole 删除及默认清空回收站行为，可能永久删除 |
| 产品 Agent 与场景 Skills | 通过 Pi SDK 接入模型，在用户授权后调用已接入业务工具；提供演唱会录像、微信本地文件和 Lightroom 照片归档场景。 | 不开放任意 shell，不处理微信加密数据库或加密图片；聊天只在本次运行期间保留 |

### 典型使用流程

1. 选择或拖入文件，查看类型、处理档位和输出位置；也可向 Agent 描述本次处理目标。
2. 确认操作后执行压缩。界面和 Agent 共用业务入口与任务调度，显示进度、结果和失败原因，并支持取消及后续重试。
3. 普通媒体在编码与文件校验通过且有体积收益后，将完整原件保存到 Backup；失败、提交前取消或无收益时不进入原件移动流程。
4. 按需归档最终结果，复制并做 SHA-256 校验后发布。可启用 AI 标签，也可只使用本人指定的标签。
5. 在“我的归档”或 Agent 中按名称、标签、日期找回文件，并打开或在 Finder 中定位。

Office 使用完整原件备份后原位替换的单独流程。APFS 去重在验证后移除旧存储副本，不另保留一份完整旧备份。备份、候选和额外副本仍可能占用磁盘，文件体积差额不等于实际释放空间。

### 数据与使用边界

编码、文件校验、备份、归档和 SQLite 在本地执行。使用 Agent 或自动标签时，对话、工具结果和用于推荐的文件名、路径及元数据可能发送给配置的模型服务；本地文件处理不等于所有请求离线。当前自动标签不分析图片画面、音视频内容或文档全文，标签推断可能需要用户纠正。

Agent 的对话授权主要由产品提示约束，部分操作另有原生确认或业务检查，当前不构成文件系统沙箱。取消不会撤销已经提交的文件操作。Office、完整系统清理、复杂媒体及跨平台兼容性均应按对应范围验证，不承诺零风险、固定压缩率或固定磁盘收益。

## 四、自主设计与第三方使用

Arkive 使用 Electron、React、TypeScript 构建桌面应用，使用 Pi SDK 接入 Agent，并调用已有媒体与文件处理工具。项目自主设计与实现主要包括：

- 将界面和 Agent 接到同一组业务入口，通过 Task 调度串联探测、编码、校验、备份和归档。
- 为视频实现抽样质量选参，为图片、PDF 和 Office 组织不同的候选、校验及发布策略，区分候选、实际采用结果和无收益状态。
- 区分完整原件、压缩输出和归档副本，使用 SQLite 记录文件状态，提供标签检索、后续重试及未完成发布事务的恢复。
- 为 APFS 去重实现逐项内容与元数据核验、原子交换及异常恢复，并将 Mole 分析、清理与候选审阅接入产品交互。

项目参考 Clop 的媒体工具调用与处理思路，复用 Mole 的分析、分类和清理能力；具体复用边界与 Arkive 自主改动见配套文档。底层编解码器、质量指标、开源框架和基础模型不作为本队自主发明申报。

第三方开源库、随包二进制、模型 API 的版本、来源、许可证和现有授权核验状态，统一列于[第三方来源与依赖说明](第三方来源与依赖说明.md)，并附[依赖完整清单](第三方依赖完整清单.csv)及[随包工具来源清单](随包工具来源清单.json)。应用不随包发布基础模型权重，本项目不申报基础模型训练或微调，也未使用训练数据集。

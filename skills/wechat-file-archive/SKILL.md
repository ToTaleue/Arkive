# 微信可读文件整理归档

目标是让用户保留需要的文件、找到重复占用，并能在以后按名称或标签找回。执行前读取[共用工具契约](../references/arkive-tools.md)，按其中的格式分流、工作副本、归档状态和重复处理规则执行。

## 明确范围与来源

取得用户指定的附件目录、独立导出目录或文件清单，区分只检查、压缩归档、去重及清理。微信账号、聊天对象、整个用户目录都不能由一个附件路径自动推成授权范围。

先判断是独立文件还是微信管理中的数据。已导出文件可以按授权直接处理；微信内部可读附件默认保留原路径，向用户说明复制到独立工作目录再压缩的方案。路径不明时请用户选定或导出文件，不猜测不同微信版本的容器结构。

用 `ls`／`find` 枚举；用户关注占用时用 `mole_analyze({ path })` 辅助定位。保存完整路径以区分不同聊天导出的同名文件。通过对应 `inspect_*` 确认可读取的实际格式；`.dat`、未知加密文件、数据库及索引列为保留／未支持项，交由微信自身管理，不靠改扩展名或读取容器推断解密内容。

完成条件：候选范围明确，应用内部文件与独立文件已经区分，未知项有保留原因。

## 提出逐项整理方案

按用户目的选择必要分支，不为“归档”默认执行去重或删除：

| 候选                                  | 默认建议                                                                 |
| ------------------------------------- | ------------------------------------------------------------------------ |
| 支持的图片、视频                      | 先探测，再按用户质量偏好压缩；说明视频 HEVC 与附加内容限制               |
| PDF                                   | 先探测；合同、票据、证件等保真需求优先无损档位，签名／加密等不支持项保留 |
| 普通 DOCX／PPTX                       | 先探测嵌入媒体；质量优先，明确原路径整份替换；内部附件在工作副本上处理   |
| TXT、表格、压缩包、数据库等未接入格式 | 保留原文件并列明当前不能压缩／直接登记归档；不冒称已进入“我的归档”       |
| 内容重复项                            | 需要去重时单独出具路径方案，不根据文件名合并                             |

标签先查询已有词库。用户说明、文件名和已有标签可以支持“课程”“合同”“项目”等建议；聊天对象、发送者、收发时间或正文内容未获得时留空。聊天正文读取、OCR 和自动图片语义识别不在本流程现有工具能力内。

向用户展示每项路径、动作、输出或工作目录、备份／归档安排及标签。若用户希望“清空微信”，先明确可处理的具体文件及影响，说明本流程不等于完整聊天备份，也不能清空加密数据库或验证聊天记录完整性。

完成条件：本批已执行的写操作都能对应到用户授权的具体方案；仅检查请求在此交付检查结果。

## 按格式处理与归档

按共用契约逐文件调用已注册工具。需要工作副本时先复制成功，再处理对应副本；复制失败只报告该项，保留原文件及可能残留的副本。

- 图片、视频、PDF：压缩并归档使用对应 `compress_*`，传 `archive: true` 和已授权标签。
- DOCX／PPTX：`compress_office({ inputPath, preset })`；确认替换和 Backup 均成功后，用 `catalog.id` 调用 `archive_file`。
- 不支持或无体积收益：如实保留并报告，按工具实际归档结果区分“已归档”“待归档”“未支持”；不为了凑齐归档数量强行处理。
- 归档成功但标签未同步：保留归档记录，报告待同步标签；后续按 ID 补打标签，不再次压缩。

输出目录保留可识别的原文件名主体，对同名文件分配不冲突的名称。当前 Catalog 记录的是本次实际输入路径；使用工作副本时，在结果中同时报告微信来源路径，不能声称 Catalog 已记录聊天来源关系。

## 按需处理重复或清理

用户要求检查重复内容时，对指定目录调用 `scan_duplicates`，展示各组完整路径和不完整扫描警告。确认用户选定的源、副本及处理方式后，按共用契约选择 APFS 保留路径去重或移除独立副本；两种方式不能互相替代。

应用管理目录中的附件若要移除，需单独说明微信可能仍保留引用；涉及数据库关系、正在写入或用途不明时，保留文件并引导用户用微信存储管理处理。通用 `trash` 不能证明微信聊天仍正常，也不能报告“已完成微信内部清理”。

用户只要求归档时，到归档和检索结果交付即结束。用户要求归档后再清理时，只把已成功归档并符合该方案保留要求的具体独立副本列入候选；未支持、无收益且未归档、备份失败、归档失败的文件不随批删除。删除授权及实际完成结果按共用契约逐项记录。

## 交付与找回

报告来源到归档的逐项映射、成功／无收益／未支持／失败／未处理数量，以及尚未解决的占用。使用工作副本时明确微信原始附件仍在，未承诺减少微信占用。

以后用户只记得文件名、部分关键词或标签时，用 `search_archives` 检索；先匹配名称，再结合已确认标签缩小范围。名称相同的多条记录展示路径和标签供区分，用户要求后按 ID 打开或定位，不重新扫描所有聊天记录。

# 演唱会与大疆录像压缩归档

目标是让珍贵录像更便于保留和查找，并让用户清楚画面、音轨、附加内容和完整原件将如何处理。执行前读取[共用工具契约](../references/arkive-tools.md)，据此处理授权、备份、归档与失败续做。

## 确定本次任务

区分用户是只看可压缩性、压缩、压缩并归档，还是找回既有录像。找回请求直接进入检索，不重新编码。

取得用户选定的录像或目录、输出位置和对画质／兼容性的要求。目录请求先用 `ls`／`find` 列候选，仅探测该范围内的视频。缺少处理档位时在方案中建议 `quality`；用户明确优先体积时可建议 `balanced` 或 `size`，不承诺某个压缩率。已授权的档位直接沿用。

完成条件：输入范围、预期动作及必要偏好明确；如果只是查看，后续停在检查与建议。

## 检查视频并提出方案

初步盘查可以选择代表文件调用 `inspect_video({ inputPath })`，据实际结果说明分辨率、时长、编码、位深、音轨数量及 `removedContents`。报告已探测数量、已知总数和样本路径，其余明确标为未探测；例如探测 5／27 个文件时，只描述这 5 个的属性，不能声称全部 27 个均为 H.264、非 HDR 或没有附加内容。Mole 占用扫描完整只证明其占用统计范围完整，不代替视频属性探测。

元数据探测不代表观看了画面或听取了声音，不能据此认定画面简单或内容重复。用文件大小与时长估算时，明确是含音轨等内容的平均总码率估算，不能称为精确视频码率，也不能只凭该数值判定码率异常。压缩潜力只作为待试压判断，样本的试压收益和画质不能替代其他文件的结果。

- 当前独立视频输出为 HEVC MP4，保留受支持的原分辨率、帧时间关系、位深与 AAC 音轨。大疆设备名本身不保证所有录制模式均支持。
- 视频重新编码属于有损处理；质量优先也不等于逐字节无损。用户坚持无损画面时，保留原片并说明当前编码流程无法满足，不擅自按有损档位执行。
- 当前支持范围为 8bit／10bit、4:2:0、非 HDR 的受支持文件；HDR、旋转、其他未支持特性或非 AAC 音轨由工具拒绝。报告具体原因并保留该项。
- `removedContents` 中的 DJI 附加数据、时间码、封面、字幕、章节等会从输出移除。原件备份保留完整旧文件；“保留所有附加内容”的要求不能由这条压缩链路满足。
- 用户要求 H.264 或明确不接受 HEVC 时，说明当前独立视频工具限制，等待用户选择是否调整目标。Office 内部 H.264 编码不等于可用于独立录像转换。

方案列出完整输入与新的 `.mp4` 输出路径、档位、移除内容，以及压缩有收益并校验成功后原件移到 Backup 的行为。录像仍由其他应用管理或用户要求原位置不变时，采用获授权的独立工作副本；也可说明可选原位置归档入口的局限。

归档标签优先复用已有词。“演唱会”可来自用户明确场景；歌手、地点、日期只依据用户说明或可靠的文件线索，无法确定时不填，不根据画面或声音臆测身份。

初步盘查的完成条件：已验证事实、推测及未探测范围清楚，给出后续验证和处理建议即可，不必为初步建议探测全部文件。

执行方案的完成条件：拟处理的候选逐项完成 `inspect_video` 核验，每项都有“可执行方案”或“保留及原因”；写操作与实际发现的附加内容损失已包含在用户授权中。已有明确授权且未出现新影响时继续执行，不为同一批重复确认。试压或小范围压缩仍是写操作，需在授权范围内进行。

## 压缩并核对

对已获授权的候选逐项调用 `compress_video`，由业务工具完成采样、试压评分、选参、完整编码与校验。无需也不能自行拼接 FFmpeg 命令或假设有截取片段工具。

压缩并归档时的参数形状如下；使用本次已确认的实际路径与标签：

```json
{
  "inputPath": "/absolute/concert/录像01.mp4",
  "outputPath": "/absolute/results/录像01-arkive.mp4",
  "preset": "quality",
  "archive": true,
  "tags": ["演唱会"]
}
```

只压缩时省略 `archive` 和 `tags`。先核对本项的 `status`、字节数、`videoCodec`、`bitDepth` 和 `qualityAnalysis`，再按共用契约分别核对 Backup、Archive 和标签。采样分数及解码检查不等于整段感知画质、演唱会声画效果或特定播放器的兼容性验收。

批量任务中可以先完成用户方案内的一条代表录像，回报真实结果；同一批已授权且没有新影响的其余文件继续执行。发现不支持特性、新的损失或发布失败时暂停受影响项，不自行降低用户要求重跑。

归档失败按 `catalog.id` 续做；无收益时报告原件保留及实际归档状态。取消后保留并报告已提交项目和未处理项目。

## 交付与找回

交付逐项结果：原文件名、源／输出字节数、压缩状态、输出路径、原件备份位置、归档记录 ID、归档路径、标签与需要用户验看的内容。不将历史 Pocket 3 样本数据套用到本次录像，不把体积差报告成磁盘已释放空间。

用户之后按歌手、活动、日期或文件名找回时，将已有事实转换为 `search_archives` 的名称或标签条件；不确定的线索先宽后窄。只有用户要求打开或定位时调用 `open_archive`，并将系统打开请求与实际播放验收分开报告。
